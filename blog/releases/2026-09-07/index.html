2026-09-07 GitHub Releases 日报：farion1231/cc-switch、JetBrains/kotlin、tashfeenahmed/freellmapi 等6个项目更新

#releases #daily #automation #cc-switch #kotlin #freellmapi #yarr #planning-with-files

farion1231/cc-switch v3.20.2 Qwen/Qwen3.8-27B

新内容

  • Grok 经 xAI 原生 Responses API 在 Codex 路由下跑通，修复工具 schema、整数浮点、多智能体消息及角色型号映射问题
  • 新增腾讯云 Token Plan、QwenCloud、AICodeWith 等预设供应商，Pi 补齐腾讯与 PPIO 支持
  • 新增 Claude Fable 5.1、GLM-5.3、GPT-6 Astra、Gemini 3.8 Flash 等七个新模型的定价行
  • Codex 内置图片生成在路由下可用，支持 /v1/images/generations 透传转发
  • Hermes「最新版本」改读 GitHub Releases，解决 PyPI 停更导致的版本探测失效
  • 接管模式下 Claude Code 模型菜单更新为 Opus 5 与 Sonnet 5，对齐最新模型别名
  • PPIO、JieKou 与 Novita 的 Claude 预设修复模型列表地址，恢复「获取模型」功能
  • 智谱 GLM 预设改指官方 Responses 端点，镜像官方模型列表并移除废弃档位

Breaking Changes

  • 预设改动只影响新建供应商，存量卡片需重新导入以获取智谱 GLM、腾讯 Pi 等新配置
  • 中途 system 消息原位转发导致严格后端（如 Nvidia、Qwen）可能再次报 400 错误
  • Sonnet 5 定价改回 $2/$10，仅纠正 seed 值安装，自定义行不动且历史费用不重算

问题修复

  • 修复 Grok OAuth 卡被 v3.20.1 安全闸误拦及接管后 Codex 卡在登录屏的问题
  • 修复 GPT-6 走 Codex OAuth 时因自报版本过低被拒为「需要更新 Codex」的问题
  • Claude Code 在 Codex OAuth 上恢复并行工具调用，默认 parallel_tool_calls 改为 true
  • 修复 Codex resume 后用量统计停摆问题，补入历史未导入的 token 计数事件
  • 修复前缀缓存每轮被打断问题，中途 system 消息不再合并到对话开头
  • 旧版 Codex（0.144.5-0.148.0）重新能加载 catalog，回填 supports_parallel_tool_calls 字段
  • DeepSeek 原生预设下 MCP 工具重新可见，修正 supports_search_tool 标志声明
  • DeepSeek 镜像 catalog 中视觉型号不再被判纯文本，正确解析输入模态
  • 修复 Kimi/Moonshot 因工具 schema 校验失败必现 400 的问题
  • Claude 会话列表不再出现幽灵「journal」会话，排除 journal.jsonl 文件干扰
  • 检查更新失败时显示真实原因，替换通用兜底文案
  • 重复的托管 ChatGPT 账号会被拒绝，防止同一 workspace 与用户身份新建第二行

JetBrains/kotlin v2.4.20 Qwen/Qwen3.5-27B

新内容

  • Analysis API 新增访问反序列化文件注解的接口
  • 支持从 Java 解析伴生块成员及扩展（Light Classes）
  • 支持 PsiClass#getRecordComponents 在 Light Classes 中的使用
  • 新增 KaScope#declarations 接口，支持按名称过滤声明
  • 新增获取 KtFunctionLikeSymbol 标签 / 名称的 API
  • KaLocalVariableSymbol 新增 isDelegatedProperty 支持
  • 新增修改 KaFunctionType 返回类型的 API
  • 引入 KtExpression.isStableForSmartCasting API 用于智能转换判断
  • 新增构建所有 KtType 类型构建 API 及创建函数式类型 API
  • J2KLIB 后端新增 -XheaderModeType=compilation 参数以提升头文件编译性能
  • 未解析引用错误现在会明确说明其作用的类型
  • 优化 KaFirExpressionTypeProvider 简单场景下的表达式类型推导性能
  • FastJarFS 避免在 JDK 16+ 解压时复制数据以提升性能
  • 修复大量属性修改为懒加载代理时 IDEA 冻结的问题
  • JVM 后端优化 typeOf 生成字节码，使用静态方法 / 字段
  • 移除无意义的 LVT 记录以优化编译性能
  • 修复 Native 平台 CastsOptimization 中的优化逻辑问题
  • 修复 AbstractFirDeserializedSymbolProvider 自 2.3.20 以来的编译性能回退
  • 简化 Analysis API 模块依赖图并统一测试运行器
  • 支持 JvmDependenciesIndexImpl 处理大型类路径的性能优化

Breaking Changes

  • 移除 kotlin.parallel.resolve.under.global.lock 注册表键
  • 弃用 analysis-internal-utils 暴露的工具类
  • 考虑移除 KaOriginalPsiProvider 组件
  • 不再发布 analysis-api-test-framework 工件
  • kotlin-compiler-common-for-ide 捆绑包移除了无关的 Analysis API 模块
  • 移除 kotlin-compiler-testdata-for-ide 工件
  • 移除 FE10 实现的测试代码
  • 将 KtReference 移至 Kotlin IntelliJ 插件
  • 将变异方法移出 Kotlin PSI
  • 确保所有 KtClassBody.parent 用法正确
  • 确保实现模块中的所有公共端点标记为 internal 或 opt-in

问题修复

  • 修复 SLC 中 expect 声明默认参数值未传播到 actual 声明的问题
  • 改进 KMP 项目中 Java/Kotlin 互操作性
  • 修复 SymbolLightAccessorMethod#isValid 对委托属性返回 false 的问题
  • 修复 SLC 中非映射 Kotlin 集合超类型被从超类型列表丢弃的问题
  • 修复私有声明不应自动生成 light classes 的问题
  • 修复 Java 类通过委托实现 MutableList 时误报红色错误的問題
  • 修复 KtAnnotationApplicationWithArgumentsInfo.normalizedArguments () 在 psi 未设置时的异常
  • 修复 MPP 中使用 expect-class 返回非 expect 成员时的误报类型不兼容问题
  • 限制 Symbol Light Classes 仅对纯 JVM 源可用
  • 修复 KMP 中 Java 文件使用期望 String 的公共声明时的误报类型不匹配
  • 修复 FIR 中调用实际枚举实例 clone 函数的编辑器错误提示
  • 修复在非 JVM 源集声明 fun clone () 时的误报错误
  • 修复移除参数后类型损坏的问题
  • 修复 Companion 块上找不到悬挂修饰符的异常
  • 修复元数据存根反序列化器在 Standalone 模式下未正确配置的问题
  • 修复 Standalone 模式下无法看到未打包 klib 包的问题
  • 修复 JvmDependenciesIndexImpl 在大型类路径下性能极差的问题
  • 修复非 JVM 源中内置模块提供不正确的问题
  • 修复 AST 与 Stub 树在非局部解构声明中的不一致性
  • 修复 KotlinDeclarationInCompiledFileSearcher 不支持可见性混淆声明的问题
  • 修复解构声明输入时找不到 fir 元素的异常
  • 修复顶层解构声明导致的 parent is ERROR_ELEMENT 错误
  • 修复 J2KLIB 中 kotlin.coroutines.SuspendFunctionN 的未绑定符号问题
  • 修复 Native 调试跟踪起始位置显示 //test.kt:1 box 的问题
  • 修复导入 konan_lldb.py 到 lldb 时打印警告的问题
  • 禁止内联后访问易失性引用
  • 修复函数值内联时作用域外类型参数的问题
  • 修复合成访问器生成时包含作用域外类型参数的问题
  • 修复 Native/JS/Wasm 中挂起转换导致非局部返回破坏 IR 内联器的问题
  • 修复 typealias 左侧 isUsedAsExpression 为 true 的问题
  • 修复 resolveToCallCandidates 在 invoke 操作符和构造函数行为不一致的问题
  • 修复 buildClassType 中的 ClassCastException
  • 修复超类型引用未感知类型别名构造器的问题
  • 若干琐碎修复（包括 PSI 移动、工厂模式替换反射、缓存提供者优化等）

tashfeenahmed/freellmapi v0.9.8 Qwen/Qwen3.8-27B

新内容

  • 桌面端仪表盘不再显示登录表单，改为使用随机密码的隐藏本地账户运行
  • 密码重置文案更新，明确说明验证码仅写入服务器日志且不会通过邮件发送，并包含 Docker 提示及锁定等待时间说明
  • 新增 ElectronHub 和 Experiential Labs 提供商适配器，支持密钥验证、共享配额分组及代理错误横幅检测
  • 路由新增冷却上限设置，防止中继故障导致整个资源池长时间不可用，同时保留提供商声明的重试时间
  • 路由压力管理新增 “全部清除” 按钮，可一次性移除所有惩罚、冷却和基准限制
  • 文档结构优化，建立分语言文档树（docs/en 和 docs/zh-cn），翻译剩余中文存根并清理过期链接与变更日志哈希

问题修复

  • 修复桌面应用会话被拒绝后回退到无法填写的 Web 登录表单的问题

OthmanAdi/planning-with-files v3.17.0 Qwen/Qwen3.8-27B

新内容

  • 将 Claude Code 钩子事件合并至单一 Python 进程运行，消除 Windows Git Bash 下因多次 fork 导致的超时与延迟问题
  • 新增 inject-plan.py 脚本作为 shell 版本的字节级等价实现，支持无 fork 的 CPython 解释器发现机制
  • 统一独立技能路由与插件路由的状态管理，共享同一轮次标记槽位和进度保护槽位，确保路径一致性
  • 优化 JSON 编码器以支持 Windows 下非基本多文种平面字符（BMP 外字符）的正确处理

安全修复

  • 修复钩子解释器在默认模式下将当前目录置于 sys.path 首位的安全隐患，防止恶意仓库通过同名模块（如 secrets.py、hashlib.py）注入代码

问题修复

  • 修复 Windows Git Bash 环境下 UserPromptSubmit 钩子超时导致计划未送达模型及后续工具调用阻塞的问题
  • 修复无规划状态目录下的响应逻辑，确保在发生任何 fork 前直接返回结果
  • 修复 awk 遍历在处理 NUL 字节、CRLF 换行符及特定正则表达式时的行为差异，确保与 shell 参考实现输出一致
