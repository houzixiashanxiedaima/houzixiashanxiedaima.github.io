  • 修复油猴脚本在内嵌页面聚焦时的快捷键问题
  • 修复 Gemini 流式错误处理、Markdown 代码围栏解析和翻译样式预览，改进设置搜索

CherryHQ/cherry-studio v2.2.2 Qwen/Qwen3.8-27B

新内容

  • 新增 Computer Use 默认开启，访问每个应用前需授权（始终 / 本次会话 / 拒绝），可在设置中管理已保存的授权；Bypass 模式跳过提示且不保存权限
  • Skills 设置新增 “导出技能到外部 Agent” 开关，新安装默认关闭，避免未显式选择时创建共享技能目录
  • DeepSeek 模型上的 Agent 在每次工具调用上方显示简短意图行，Agent 会话默认展开工具步骤并折叠同类重复调用
  • 新增波兰语支持
  • MCP QVeris 现以 OAuth 浏览器登录为主要凭据，QVERIS_API_KEY 作为可选回退，无需 API key 即可启用
  • 文件大小在全应用中统一格式
  • 优化 Agent 会话详情排版、图标对齐、间距及无工作区占位符

Breaking Changes

  • Computer Use 默认开启，若不需要请在设置中关闭
  • SiliconFlow 移除 OAuth 登录，若此前通过 OAuth 登录需改为手动输入 API key

问题修复

  • 修复 CherryIN Claude Sonnet 4.5 工具请求因 Bedrock 参数校验错误而失败的问题
  • Claude Opus 5.5 在 AWS Bedrock 上现使用自适应推理
  • SiliconFlow 改用手动输入 API key，移除已废弃的 OAuth 登录
  • 将 “输入超出上下文限制” 错误识别为上下文长度拒绝，触发现有恢复指引
  • 本地 Markdown 文件链接现可在无 artifact 预览的聊天界面中打开
  • 修复首次 composer 工具栏激活在加载期间丢失的问题，内部标签导航不再阻塞交互
  • 修复流式审批请求先于其工具源到达时 AskUserQuestion 卡片缺失的问题
  • 修复所有问题均被跳过时最终 AskUserQuestion 的 Skip 按钮卡住的问题
  • Pi Durable 读取工具调用展开后不再显示空白文件详情
  • Pi Durable Agent 现自动加载 AGENTS.md 等工作区指令文件
  • 普通 MCP 工具现可通过 Pi Durable 运行时的工具搜索发现，不再返回 “未找到匹配工具”
  • Agent 工具指引现将延迟工具视为可通过发现机制使用，并使用会话中的精确工具名，解决 Agent 报告可用工具缺失的问题
  • 当推理耗尽响应预算时提供准确的输出 token 限制指引，DeepSeek V4.1 Flash 容量对版本化模型 ID 解析正确
  • API Gateway 不再丢弃第三方模型的 Claude Code MCP ToolSearch 结果
  • Code Mate 统一网关模型选择器现列出仅对 Agent 可用的 Cherry Cloud 模型
  • Doctor 不再对 CherryAI 和 Cherry Cloud 误报缺少 API key 或模型列表不可用，Cherry Cloud 会提示需要登录
  • 深色模式下网站 favicon 保持可见，带浅灰色背板且保留原始颜色
  • 更新对话框中的 Release Notes 现遵循应用解析后的语言，包括跟随系统语言的情况
  • 若干琐碎修复与 CI / 构建优化（依赖替换 mime-types 为 mime、e2e 回归测试修复、发布构建并行化等）

yetone/alma-releases v0.4.617 - v0.4.618 Qwen/Qwen3.8-27B

  • 附件现支持后台上传：图片立即显示并带进度指示，发送时等待上传完成以确保文件完整

tw93/Pake V3.19.0 Qwen/Qwen3.8-27B

新内容

  • macOS 上 —icon 参数支持 Icon Composer .icon 包，应用图标在 macOS 26+ 跟随浅色、深色和着色外观变化…
  • Windows 和 Linux 新增快捷键：Ctrl+W 关闭窗口、Ctrl+Q 退出、Ctrl+L 复制地址、Alt + 左右方向键前进后退…

  • Linux 上网页加载失败时显示站点名和重试按钮，替代引擎原始报错；Linux 和 Windows 上渲染进程崩溃后自动重新加载页面

  • 开启查找功能后，Notion、Google Docs 等自带搜索的网站在 Windows 和 Linux 上保留其自身的 Ctrl+F 行为

code-yeongyu/oh-my-openagent v5.1.70 Qwen/Qwen3.8-27B

新内容

  • 新增 omo login 支持在终端直接登录，无需桌面应用
  • 新增 Windows 计算机使用实时测试层，覆盖多种场景
  • 新增 senpi contextFiles.globalPath 设置，支持从指定文件加载全局上下文
  • 新增计算机使用 v3 引擎结果与错误契约，明确七种有效交付 / 重试组合
  • 新增交互式独立发布启动时异步检查并安装更新，每日最多一次
  • 新增计算机使用 v3 引擎契约根，包含方法表、engine.hello 及配置表
  • 新增计算机使用 v3 引擎工作区注册，包含 10 个 crate 和 7 个包

安全修复

  • 修复桌面内存同步在处理超大响应时的内存溢出风险，zod 升级至 4.6.7 并限制数组大小
  • npm 包 omo-ai、oh-my-opencode 等仅携带 zod 4.6.7，避免受 GHSA-mrhx-c7xc-m3w5 影响
  • 编译后的 omo-* 二进制文件中仍包含一份 zod 4.6.2 副本，用于解析本地 Claude Code 子进程输出

Breaking Changes

  • 移除 omo login —new-device，OmO 服务每台电脑仅保留一个设备，存储的登录不可读时需通过桌面应用恢复
  • 当凭据存储锁定时，omo login 提示解锁并重试；设备服务已安装但不响应时，提示打开 OmO 桌面应用启动服务
  • omo login 拒绝不再建议 omo logout，未知刷新结果时优先指向共享桌面应用登录，仅在必要时提供重新开始步骤

问题修复

  • 修复 omo remote bootstrap 在 macOS 上无法安装设备服务的问题
  • 修复浏览器技能使用 omowright 0.3.1，改进页面导航、清理失败报告等
  • 修复 omo remote send 在等待模式下静默问题，现在会在 stderr 报告排队状态
  • 修复 thread_create 无 cwd 时在新线程打开调用会话文件夹而非引擎进程文件夹
  • 修复 computer-v3-guards —residue 未报告悬空符号链接的问题
  • 修复独立 omo update 现在直接安装发布版本而非打印 curl 命令
  • 修复启动时代理扩展目录只读导致失败的问题，Claude 连接测试保留脱敏错误信息
  • 若干琐碎修复（协议文档描述、web 测试夹具、EQ.omo linux-x64 goldens 重新录制）
