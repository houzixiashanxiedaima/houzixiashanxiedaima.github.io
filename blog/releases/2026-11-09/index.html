yetone/alma-relay v1.3.1 - v1.4.0 Qwen/Qwen3.8-27B

新内容

  • 新增协议 3，为每个流提供独立的信用额度
  • 中继在注册时通告窗口大小（1 MiB），并在响应体或 WebSocket 字节传输至手机时发送确认
  • 桌面端保持每个流最多一个窗口的未确认数据
  • Node 版从 res.write/ws send 回调中发送确认，若流在 STALL_TIMEOUT_S 内未写入任何应写数据则被切断
  • Cloudflare 版在手机拉取响应字节及发送 WebSocket 消息时进行确认
  • 当手机读取速度低于桌面发送速度时，中继现在会暂停读取该桌面的 socket，防止积压
  • 在桌面 socket 暂停期间，中继每 5 秒发送一次主动 pong，保持连接不断开（兼容所有 Alma 版本）
  • 新增 FLOW_HIGH_WATER_MB / FLOW_LOW_WATER_MB 配置项（默认值 8 / 1），用于控制流量高 / 低水位阈值
  • 超过 2 秒的暂停、对端状态以及被切断的手机现在会记录在中继日志中

Breaking Changes

  • 设置 RELAY_PROTOCOL=2 可关闭协议 3，旧版桌面端不受影响
  • 需要支持协议 3 客户端的 Alma 桌面端（PR yetone/alma#492）

问题修复

  • 修复手机停止读取导致 Node 版停止读取整个代理套接字，进而使该桌面上其他手机、herdr 查看器和 E2E 隧道全部停滞的问题
  • 修复 Cloudflare 版将桌面端发送的数据保留在 Durable Object 内存中的问题
  • 修复启动行错误显示版本号 1.2.0 的问题（应为 1.3.x）

  • 启用 TOTP 后，POST /etapi/auth/login 接口现在需要 code 参数
