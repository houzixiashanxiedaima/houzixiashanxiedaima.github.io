### [yetone/alma-releases v0.4.796 - v0.4.866](https://github.com/yetone/alma-releases/releases) <sup>Qwen/Qwen3.8-27B</sup>

**新内容**
- 新增 alma herdr run 命令，支持在终端面板输入并执行命令，可通过 `--wait` 参数显示执行后的屏幕
- 新增 alma herdr keys 命令，支持向终端面板发送 Ctrl+C、Enter 或 Escape 等控制键
- 新增 alma herdr read 命令，用于显示当前屏幕内容，支持通过 `--lines` 参数查看历史记录
- 上述新命令均通过 /api/herdr/rpc 接口实现，因此在启用 `--computer` 模式下也可使用
- 现在可以与拥有 shell 但没有 agent 的终端面板进行交互，此前这类面板无法接收任何命令
- 截图处理改为分批执行并加入暂停，优化资源占用
- 截图缩放时保持原始宽高比，避免拉伸变形
- 新增基于 Go 的文本和语音消息处理流程，并保留回退至 Node.js 处理的选项
- Telegram 媒体和消息下载现由 Go 服务处理，支持私聊、定向聊天和群聊中的图片、视频、文档、文本及聊天记录
- 语音转录仍使用 Node 服务
- 可通过设置 ALMA_NODE_TG_MEDIA=1 或 ALMA_NODE_TG_GROUPMEDIA=1 保留之前的基于 Node 的媒体处理方式
- 在设置 → 个人代理下新增 Persona 与记忆设置
- 新增主对话界面，并列出过往对话（Lifesign）
- 浏览器导航与阅读操作（后退、前进、刷新、关闭、读取及 DOM 读取）现直接在原生应用中运行
- 浏览器评估功能现直接在原生应用中运行，返回格式化结果和错误信息
- 应用内浏览器的打开链接、点击和输入操作现直接在原生应用中运行
- 对话开始时的压缩处理现直接在原生应用中运行，包括紧急回退和归档摘要
- 任务执行现在原生运行在 Go 中，直接处理任务状态、结果、crew 活动和工具日志，以提升性能和可靠性
- 无显著变更
- 工具审批处理现由 Go 服务器管理，包括待审批卡片、超时、始终允许授权、跳过以及通过 HTTP/WebSocket 和 relay 的交接
- Node 客户端现在通过保持打开的 POST 请求来请求工具审批，停止请求会取消等待中的 Bash 审批卡片
- 图片上传失败时保留在编辑器中，支持原地重试，避免文件丢失

**问题修复**
- 修复标题生成逻辑，改为渐进式处理并保存，防止打开 Alma 时超时及重启后重复请求
- 优化通知标题优先级，后台命名任务排队等待而非直接超时
- 修复粘贴图片显示问题：现在以缩略图（最大 360×280）形式展示，避免大型 Retina 截图占满聊天栏；点击图片仍可全屏查看
- 优化无 agent 面板的错误提示：发送失败时建议改用 run 命令
- 修复 macOS 上活动轮换器重新编码旧截图时的高内存占用问题
- 修复资源查看器中长列表在左侧栏的对齐及溢出对话框问题
- 修复 Go 轮次中逐字流式传输长回复时可能停滞的问题，服务器现在能更高效地处理分块文本
- 修复中文、日文和韩文查询的网页搜索问题，当搜索引擎返回无关页面时回退至 360 搜索，避免机器人检测页面
- 修复中文、日文或韩文标题链接（百分号编码）无法正确滚动到对应标题的问题
