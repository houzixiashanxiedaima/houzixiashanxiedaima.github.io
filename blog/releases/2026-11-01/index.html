yetone/alma-relay v1.0.1 - v1.2.0 Qwen/Qwen3.8-27B

新内容

  • 新增中继协议 v2，支持流式传输请求体，上传按 256 KiB 分片转发并带 4 MiB 窗口确认
  • 协议 v2 使用二进制 WebSocket 帧替代 base64 JSON，消除约 33% 的编码开销
  • 协议 v2 引入可配置的最大请求体限制 MAX_BODY_MB（默认 100 MB），v1 在 Cloudflare 上仍为 24 MB
  • 协议版本自动协商：桌面端注册时声明 proto: 2，中继据此选择协议，旧版客户端保持兼容
  • 新增 RELAY_PROTOCOL=1 环境变量，可在不重新部署桌面端的情况下回退至协议 v1
  • Node 版实现端到端流式传输；Cloudflare 版虽受边缘缓冲限制，但仍解除 24 MB 上限并避免占用 Durable Object 内存
  • Node 版新增流控与资源限制：背压机制防止中继缓冲整个数据流
  • Node 版新增多项资源上限配置（如 MAX_BUFFERED_MB、MAX_AGENTS 等）
  • Cloudflare 版 LOCATION_HINT 现在能真正移动隧道，优化桌面端重连逻辑
  • Cloudflare 版新增 RELAY_TOKEN_MESSAGE 配置项，用于自定义无效令牌提示
  • Cloudflare 版 worker.mjs 现随包发布，支持直接依赖 alma-relay 部署
  • APNs 推送支持 Live Activity（pushType: ‘liveactivity’、priority），与 Alma 托管中继保持一致

Breaking Changes

  • 帧大小上限调整以匹配 Cloudflare 版：Agent 帧降至 32 MiB，手机消息降至 24 MiB（原均为 256 MiB）

问题修复

  • 拒绝读取超大 Content-Length 请求体，防止潜在资源滥用
  • 要求 Agent 套接字在 10 秒内完成注册，提升连接健壮性
  • 限制手机在桌面端打开前最多发送 4 MiB 数据
  • Cloudflare：WebSocket 关闭握手现在能正常完成，手机不再等待约 10 秒后以 1006 结束
  • Cloudflare：桌面端在响应头返回前出错时，现返回 502 并附带桌面端错误信息，而非 504
