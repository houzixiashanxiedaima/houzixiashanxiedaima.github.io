code-yeongyu/oh-my-openagent v5.0.0 - v5.0.1 Qwen/Qwen3.8-27B

新内容

  • OmO Native 升级至 senpi 2026.9.27，包含多项底层修复
  • npm、pnpm 和 Yarn 安装现在在已安装 Bun 1.4.0+ 时默认使用 Bun 运行（可通过 OMO_RUNTIME=node 保持 Node）
  • 本地 omo install 的启动器更新指令改为 bun add -g omo-ai，与全局安装保持一致
  • 写作功能路由调整：以 Claude Opus 5.5 (low) 为首选，不再使用 Claude Fable 5.1…
  • Web 端新增 crafted 部分的变形动画效果及闭式弹簧时间驱动变形支持
  • OmO Native 成为默认稳定版本，通过 bun add -g omo-ai 安装
  • 新增 mass ulw 功能，将任务转化为依赖图并路由至不同模型执行
  • 引入 Kibitzer 功能，支持 JavaScript/Python eval cell 及并行工具调用
  • 内置 omowright 浏览器自动化，支持复用现有登录状态及反检测模式
  • 新增基于 Git 的 Markdown 记忆系统，包含自我块、反思及后台工作器
  • 性能优化：冷启动时间从 5.8 秒降至 850 毫秒，上下文消耗大幅降低
  • deep-low 委托通道默认使用 GPT-5.6 Sol Fast (medium) 模型
  • 发布流程更新：稳定版直接发布至 latest 频道，预发布版至 beta 频道
  • 迁移工具 omo setup 自动携带 OpenCode 配置（API 密钥、MCP 等）
  • TUI 实时显示任务进度、阶段变更及计划状态报告

Breaking Changes

  • 写作功能不再回退到其他模型家族：如果唯一连接的 Claude 模型是 Fable 5.1 且未固定类别，写作功能将不可用
  • OpenCode v1 和 LazyCodex 插件转为降级支持，新功能优先在 OmO Native 发布
  • 建议移除旧的 oh-my-openagent 4.19.x 全局安装，改用新的 omo-ai
  • 仅拥有 GPT-6 Sol 的账户不再默认显示 deep-low 通道，需固定类别模型

问题修复

  • 修复扩展在 Bun 1.3 上加载失败的问题（包目录作为入口或依赖 ajv 等需要 JSON 文件的包时报 Cannot find module）
  • 修复强制推理模型（如 GLM 5.3）无法生成会话标题的问题，现请求最低推理级别并将失败写入日志而非报错
  • 修复单个图片被拒绝后导致后续所有轮次（包括纯文本）失败的问题，被拒图片替换为文件备注并允许继续
  • read 工具现在能识别路径带引号的文件（如 Windows 资源管理器 “复制为路径” 产生的格式）
  • 修复稳定版启动横幅错误显示 beta 标签的问题，现在正确显示版本号
  • 修复同一时刻派生其他会话时终端输出混入多余换行符的问题
  • 修复过期的 Claude 登录凭据导致首次无头 / 桌面轮次失败的问题，模型配置解析现在会跳过无法刷新的凭据并继续尝试下一个提供商
  • 修复委派任务在提供商拒绝凭据后仍重试同一提供商的问题，现在跳过该提供商并提示重新认证方法
  • 修复 Web 端在不支持滚动时间线的浏览器中 reveal 内容不可见的问题
  • 修复 Web 端 Firefox hero 相关样式问题
  • 若干琐碎修复（CI payload 检查版本、README 文档分类、测试断言等）
  • 修复 Cursor CLI 首轮请求被误判为空计划提醒的问题
  • 修复 handoff 块重述请求时被误判为重复轮次的问题
  • 修复 Bedrock 工具 schema 相关问题 (#8615)
  • 修复主机会话所有权问题 (#8659)
  • 修复手动分类 QA 问题 (#8302)
  • 修复 doctor 迁移命令在导入时而非使用时解析的问题
  • 跳过凭证无法解析或拒绝的提供商以优化模型配置文件
  • 升级 senpi 引擎至 2026.9.26 版本
