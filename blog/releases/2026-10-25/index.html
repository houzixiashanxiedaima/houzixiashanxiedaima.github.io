安全修复

  • 收紧信任机制：帮助输出、shim、钩子、配置写入及 shell 补全不再未经同意即信任项目或执行其代码
  • 验证失败时采取保守策略：强制校验固定校验和、Node 签名、SLSA 溯源及 GitHub 认证，避免因 404 或缺失文件而跳过
  • 隔离恶意输入：归档、资产名、版本、锁文件及 HTTP 响应无法越界写入、无限占用内存 / 磁盘或挂起提示符
  • 防止凭据泄露：安装路径、锁文件、日志及重定向中不再显示凭据信息
  • 安全模式 (MISE_SAFE=1) 增强：拦截项目懒加载工具、[deps]、path: 版本、spm install_command…
  • 安全模式 (MISE_SAFE=1) 增强：拦截项目模板中的 env 和文件系统助手，限制 toml 模板语言并强制 bin_path 位于工具安装目录内
  • 按 TAB 键不再运行未信任的任务代码；动态补全器仅对受信任配置生效，并修复 fish 和 PowerShell 的引号处理问题
  • 钩子命令在加载时一次性渲染，防止目录名包含 {{exec (…) }} 时从 cd 钩子执行代码…
  • 任务沙箱逃逸减少：—allow-write 拒绝指向项目外的符号链接，—deny-net 拦截其他 socket 族、io_uring 及 x32 系统调用
  • 任务沙箱逃逸减少：空 allow_write 现在阻止所有写入而非关闭沙箱；macOS 始终使用 /usr/bin/sandbox-exec…
  • 限制 HTTP 响应体大小为 128 MiB，慢速响应受 http_download_timeout 限制…

Breaking Changes

  • lockfile_mode = “generate” 成为默认值，安装时会重建 mise.lock 并锁定其他平台，如需旧行为需设置为 “merge”
  • 信任提示变更：在未信任同级配置的目录中执行 mise set/unset/tasks add 会要求信任或在无终端时失败…
  • 工作树与 include 变更：手动移动的工作树需执行 git worktree repair 才能共享信任…
  • 项目 .miserc.toml 模板限制：读取 env 或使用 arch ()、os () 等之外函数 / 循环的模板不再渲染，需移至全局 .miserc.toml
  • 安全模式下，无默认值的 env 变量读取会导致项目模板渲染失败；指向私有 forge 或 netrc 保护服务器的项目无法再列出版本
  • Node 镜像若未复制 .sig 文件或早期版本缺失签名文件，需设置 node.gpg_verify = false
  • SLSA 验证变更：github: 工具若设置 slsa_signer_identity 但从分支而非标签构建则不再验证…
  • packslip 变更：仓库重命名后，无仓库 ID 的 pin 需执行 mise packslip forget .
  • GitHub Enterprise 变更：http: 工具、aqua 包及远程任务在 /api/v3 URL 上不再自动获取 GitHub token…
