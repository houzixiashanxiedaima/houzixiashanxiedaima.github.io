jdx/mise v2026.10.0 Qwen/Qwen3.8-27B

新内容

  • 新增 Homebrew cask 独立应用目录（appdir）配置，支持覆盖全局设置并展开～/

安全修复

  • .tool-versions 中的内联工具选项现在需要信任，防止未受信任项目泄露 GITHUB_TOKEN
  • Keyless cosign 验证现在检查签名者身份，防止错误工作流签名的 bundle 通过验证

Breaking Changes

  • vfox 工具插件使用 keyless cosign 时必须固定身份标识
  • Alpine/musl 主机上如果注册表条目指定 gnu 资产但发布也包含 musl 构建，现在安装 gnu 构建…
  • 脚本中检查 Ctrl-C 后的退出状态应从 1 改为 130

问题修复

  • 修复锁定 SLSA 安装在无注册表签名者时的失败问题
  • 修复 musl 主机上 aqua 工具安装失败的问题
  • 修复 mise backends switch 处理过期锁条目的问题
  • Ctrl-C 中断命令现在以状态码 130 退出，与 mise run 保持一致
  • 拒绝信任提示时跳过当前运行的配置而非直接失败
  • 移除过期的 latest 运行时目录一次性启动迁移逻辑
  • 诊断过期的 dotfile 历史监视器，提示用户运行 mise bootstrap services apply
  • Java 缺失元数据错误现在显示目标平台信息

code-yeongyu/oh-my-openagent v5.1.9 - v5.1.10 Qwen/Qwen3.8-27B

新内容

  • 桌面应用受限模式下，代理内部工具不再请求审批，且 eval 单元中的 bash 调用不再挂起
  • 随应用分发的文件不再被视为外部路径，Windows x64 冷启动后首个 Python 单元可正常工作，委派任务保留超时设置并运行在模型支持的思考级别上
  • 此版本基于 senpi 2026.10.1-3 引擎运行

问题修复

  • 修复 omo -p 在委托任务完成后无法退出的问题，避免 CI、cron 等脚本挂起
  • 修复交互式会话中每个委托任务泄漏回环桥接服务器及其套接字的问题
  • 修复子进程销毁时未执行引擎内置扩展的 session_shutdown 处理器导致进程存活的问题
  • 修复主机重启后恢复的委托任务状态报告错误，拒绝或超时的提示现在正确报告为丢失而非成功重连
  • 修复 Windows x64 冷启动后首个 Python 单元因内核未就绪而失败的问题，改为等待内核自身就绪阶段并在错误中指明停滞阶段
  • 工具搜索在重新加载或会话替换后保持可用
  • 仅支持切换的推理模型仅提供其 API 接受的思考状态
  • Claude 订阅下长运行在会话丢失且重发对话被拒为过长时仍能存活，且代理通过工具读取的图片不再作为新附件重发
  • 进程内运行的委派任务保留用户的超时和重试设置（如 streamStartTimeoutMs），而非使用内置默认值
  • 内置类别链仅命名其模型接受的思考级别，子会话不再触发回退日志验证警告，每级按声明级别运行而非静默截断
  • macOS 上重复权限拒绝不再声称隐私面板刚刚打开，而是指向之前打开的面板或在首次尝试失败时提示用户打开它
  • 若干琐碎修复与构建调整（Rust 工具链固定至 1.99.0、fake clock 中弃用的 fetch_update 替换、CI 测试临时目录修正等）
