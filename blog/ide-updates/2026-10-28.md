### [Claude Code 2.1.311 → 2.1.312](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) <sup>Qwen/Qwen3.8-27B</sup>

**新内容**
- 新增 oidc.user_id_claim 配置，支持通过 id_token 中除 sub 外的声明（如 Microsoft Entra ID 的 oid）识…
- 全屏模式下点击排队消息下方的“立即发送”提示即可直接发送该消息
- 优化提示词中的努力程度指示器：任务中途更改时提示可能需等待下一条消息，不再适用时自动清除备注
- 改进云会话中 WebFetch 错误提示：域名无法解析时说明可能不在允许的网络域内，并提示 Claude 指定需允许的域名
- 云会话从 CLI 启动时，名称和分支名现由服务器提供
- 提示词和代理钩子并发执行上限调整为每会话最多 24 个（含子代理），超时等待超过事件超时的最多 12 个；不足 1 秒的超时按 1 秒计
- OpenTelemetry mcp_server.name 现报告来自官方 Anthropic 市场插件的固定 URL 远程 MCP 服务器的真实名称…
- [VSCode] 用量限制重置显示具体时间（如“下午 3:10 重置”），并统一称为“5 小时限制”
- [Cloud sessions] 创建或编辑在云端运行的例程时，模型选择器新增努力程度选项
- [Cloud sessions] 云环境设置中的脚本框新增带颜色、行号和复制按钮的 Bash 编辑器
- [Cloud sessions] 改进 Claude 向云会话添加仓库时的步骤展示：打开后显示简短表格而非原始 JSON
- [Claude Tag] 改进 Slack 中 Claude Tag 的重试通知：明确显示当前使用的模型或速率限制情况，而非通用 API 错误

**Breaking Changes**
- Bedrock、Vertex、Foundry 和 Mantle 对 Claude Code 不识别的模型名称改用较短的系统提示词…
- 标记消息后的自动模型切换现也覆盖 Claude Code 不识别的模型名称；设置 CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1…
- 子代理的 autoCompactWindow 现会降低 CLAUDE_CODE_AUTO_COMPACT_WINDOW 设置的值（此前无效），但仍不会提高该值
- Claude Code 停止发送 claude_code.safety_event OpenTelemetry 事件

**问题修复**
- 修复从 VS Code 扩展登录后，托管设置和组织策略在会话剩余时间内未被获取的问题
- 修复 Claude 仅读取大型 CLAUDE.md、规则文件或 @-包含文件开头后就覆盖整个文件的问题；Write 工具现要求完整读取或就地编辑
- 修复在 git 仓库中通过 Bash cd 深入目录后，按目录和路径配置的 skills 无法找到的问题
- 修复终端中恢复会话后首次回复在下次恢复时偶尔缺失的罕见情况
- 修复无效名称的命令导致所有命令加载停止，可能导致 claude -p 无输出的问题
- 修复 Read 工具在处理 PDF 页面时因旧会话文件清理同时运行而偶发失败的问题
- 修复 spinner、OpenTelemetry effort 值和转录在模型应用前就显示新选定的努力程度级别的问题
- 修复 /model 和 /effort 缓存警告中关于重新读取等待下一条消息的误导性说明
- 修复部分会话在最后一条消息仅在句中提及等待项时仍显示为等待用户的问题
- 修复 agent 视图在退出前用 Ctrl+C 清空输入文本后，下次启动时恢复该文本的问题
- 修复 agent 视图在空 ! 输入下用 Ctrl+D 退出后以 shell 模式重新打开的问题
